# torsorlab

The lab site. Jekyll, no theme, local-only for now.

```sh
make serve    # http://localhost:4000
make build
make check    # build, then assert the collections are wired correctly
make art      # regenerate assets/img/*.svg
make manuals  # copy the built torsor-writing manuals in (BUILD=1 to rebuild them first)
```

Voice and tone rules live in `AGENTS.md` — read that before writing site prose.

## Where to edit what

| You want to change | Edit |
|---|---|
| Colors, fonts, spacing | `_sass/_tokens.scss` — the only file with hex values |
| Nav links | `_data/nav.yml` |
| Home page words | `index.md` (front matter carries the hero) |
| A tool's blurb or status | `_tools/<tool>.md` |
| A doc page | `_docs/<tool>/<nn>-<slug>.md` |
| Marginalia on a doc page | the `notes:` list in that page's front matter |
| Whether a doc page links to a manual | `manual: true` in its front matter |
| Site title, description | `_config.yml` |

Adding a tool is one file in `_tools/`. Adding a doc page is one file in
`_docs/<tool>/` — no index anywhere needs updating.

## Doc page front matter

```yaml
title:      write-manual
tool:       torsor-writing            # must match a _tools slug
slug:       write-manual
permalink:  /tools/torsor-writing/write-manual/
order:      1                         # matches the filename prefix
summary:    One line, shown in the tool's doc index.
notes:                                # optional marginalia
  - title: Heading
    text: A sentence or two.
```

## Design

Ported from `torsor-style/style-b`. Site pages use Direction A (topographic,
cream); doc pages use Direction B (spinal, lavender). The artwork in
`assets/img/` is generated by `bin/gen-art.py`, a port of that design's
`support.js` — the site ships no runtime JavaScript.

## The manuals

Three skills — `write-paper-guide`, `write-critical-guide`, and
`write-review-and-repair` — have full user's manuals, authored and built
elsewhere (in the `guides/` directory beside the plugin repo). `make manuals`
copies the built HTML and PDF into `tools/torsor-writing/<skill>/manual/`, and
the doc page links to them when its front matter says `manual: true`.

`bin/sync-manuals.py` refuses to copy a manual whose LaTeX source is newer than
its build output — a stale manual on the site is worse than a missing one.
Rebuild it, or run `make manuals BUILD=1` to have the guides' own Makefiles do
it. Point it elsewhere with `make manuals GUIDES=/path/to/guides`.

Note that `bin/` holds the build scripts and `tools/` is site content — the
manuals live under `tools/` because that is the site's URL space.

## Docs are hand-written

The doc pages are deliberately *not* synced from the source repos. Upstream is
the source of truth for code; this site is a separate, curated telling. When a
tool changes, update its pages here by hand.

`_tools/torsor-writing.md` and `_docs/torsor-writing/` were drawn from the
manuals in `guides/`, and — for the eight skills without a manual — from the
`SKILL.md` files in https://github.com/torsor/claude-plugins (at 0.10.1).

## Deploying

Live at **https://lab.torsor.org**, served by GitHub Pages from
`torsor/torsorlab`. Every push to `main` runs `.github/workflows/pages.yml`,
which builds the site, runs `bin/check.py`, and deploys. A failing check fails
the deploy.

The custom domain comes from the `CNAME` file in this repo; DNS for `lab` is a
CNAME record to `torsor.github.io`, managed at DreamHost.

To check a deploy:

```sh
gh run list --repo torsor/torsorlab --limit 3
gh api repos/torsor/torsorlab/pages --jq '.cname, .status'
```
